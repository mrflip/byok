# Thread 15: e2e_home (2026-10-16)

Branch `20261016-e2e_home`, PR [#111](https://github.com/mrflip/safebyok/pull/111), stacked on [#105](https://github.com/mrflip/safebyok/pull/105) (the line's top). Justify: green at the root (core 1144, convex 159, e2e 123, root 124, the rest unchanged).

* **Built**: `e2e/`, the private workspace package `safebyok-e2e` (in `pnpm-workspace.yaml`, with its own lint, typecheck, test and justify scripts, so the root's `pnpm justify` runs it). It holds `tests/convex/`: the fake Convex deployment (`fake-deployment.ts`), a host built from `safebyok-convex`'s published entries (`test-helpers.ts`), and the `convexVaultDB` battery (`convex-vault-db.test.ts`), run over both `ConvexClient` and `ConvexReactClient`. `safebyok-convex` drops `react` from its devDependencies and imports nothing of React's anywhere. The root eslint ignores `e2e/**`; `scripts/release.ts` treats `e2e/` as it does `demos/` (a public package there is refused), with a test. CLAUDE.md's *Layout*, the root and convex READMEs, and PROCESS.md name it.
* **Decisions taken**:
  * *Everything that needs the fake deployment moved, not only the React cases.* The plan said to move the tests using a real `ConvexReactClient`. But the file runs nearly every test over both clients from one table, and the fake deployment is one file that both clients share; keeping the `ConvexClient` halves in `safebyok-convex` would have meant either a copy of the 250-line fake, or `e2e` and `safebyok-convex` importing each other's `tests/` by relative path. So the file moved whole, `git mv`'d and changed only in its imports: `../src/index` becomes `safebyok-convex`, `../src/server` becomes `safebyok-convex/server`. What stays in `safebyok-convex/tests/convex-vault-db.test.ts` is the pure `toConvexLockbox` suite. The cost: `safebyok-convex`'s own coverage of `convex-vault-db.ts` is now nil, and its tests now live a directory away. If the Coach would rather keep the `ConvexClient` cases beside the adapter, the way is to publish the fake deployment through a test-only entry of `safebyok-convex` (a new public surface, so a Coach's yes), and have both read it.
  * *Two assertions adjusted because `e2e` reads only published entries.* "Declares the component's own limit" now asserts `maxLockboxes` is 8000, not `=== MaxVaultLockboxes`; the damaged-lockbox test builds its record without `toConvexLockbox`, which only drops an undefined `note`, and that record has none. I checked that the first still fails when the limit changes (mutated `MaxVaultLockboxes`, saw it fail, reverted).
  * *`heavyBox` and `RealPassphrase` are copied into `e2e/tests/convex/test-helpers.ts`* (a few lines); the adapter's own tests still use theirs.
  * *Packages are read as a consumer reads them.* `e2e`'s `pretest` builds `safebyok` and `safebyok-convex` (as every package's does) and the tests resolve `dist/`, except `safebyok-convex/test`, which ships as source.
  * The changeset is empty (`20261016-e2e_home.md`): a dev-dependency and a README line in a public package, no behaviour.
* **Deviations**: the plan says "drop `react` (and `react-dom`, `@testing-library/*`, if only those tests used them)": `safebyok-convex` had only `react`. No `jsdom` or testing-library in `e2e/`; the Convex clients need neither.
* **Discoveries**: `convex/react` imports React at module load, which is why `react` was a dev dependency at all; `e2e/` now has the only `react` among the Convex tests. The fake deployment's comment names both clients, so it needed no edit. `e2e/` is `edge-runtime` like convex's tests (convex-test's `import.meta.glob`); a Vue or React-rendering test that wants jsdom sets `@vitest-environment jsdom` at the top of its file, as the demo does.
