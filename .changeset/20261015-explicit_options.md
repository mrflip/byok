**Breaking:** `openVault`'s `keyDeriver` is required, and so is `VaultProvider`'s: `openVault` no longer falls back to the Argon2id deriver, so an app that never imports it never ships it. The new entry point `safebyok/browser` exports `browserOpts({ dbName }?)`, the browser's defaults as a bag of options (`keyDeriver: argon2idWebV1Deriver`, `deviceDB: idbDeviceDB({ dbName })`): a browser app spreads it into `openVault` (or `<VaultProvider {...browserOpts()} />`) beside its own `vaultDB`, and may drop its own `deviceDB`. `argon2idWebV1Deriver` is still exported from `safebyok`, for an app that passes it itself. An `openVault` without a `keyDeriver` refuses with kind `bad_option`. Vaults already stored read as before. **Also renamed, before the first release makes them costly:** the snapshot's `expiresAt` is now `askPassphraseAt`; the `openVault` and `VaultProvider` option `rememberForMs` is now `forcePassphraseReentryHours`, counted in hours (fractions allowed: `0.25` is fifteen minutes) and refused with kind `bad_option` unless above zero; and the exported `SevenDaysMs` is replaced by `ForcePassphraseReentryHours`, its default, 168. A host passing `rememberForMs: ms` passes `forcePassphraseReentryHours: ms / 3_600_000`. Remembered unlocks already on a device keep their deadline.
